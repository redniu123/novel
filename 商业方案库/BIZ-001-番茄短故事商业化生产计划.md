# BIZ-001：番茄短故事商业化生产计划

状态：`approved_for_manual_pilot`

版本：1.0

制定日期：2026-07-23

适用范围：基于 InkOS 1.7.0 短篇生产链的番茄短故事人工投稿验证

## 1. 执行摘要

本方案把商业场景锚定为：

> 为番茄短故事平台稳定生产可签约、可结算、具备 IP 改编潜力的原创脑洞悬疑短故事。

第一阶段不建设短视频、配音、数字人、多平台矩阵、自动登录或自动投稿。系统负责选题候选、大纲、正文、审查、修订和包装；人工商业总编负责选题裁决、重点改稿、原创与合规确认、合同审阅、投稿和结算确认。

这项业务是否成立，只用三个结果判断：

```text
实际签约
+ 实际到账
+ 计入全部落选稿后批次毛利为正
```

活动奖金、爆款收入和 IP 改编收入属于上行收益，在基础商业模型中按 0 计算。

## 2. 当前市场窗口与事实边界

截至 2026-07-23，番茄官方创作活动页显示：

- 第三期“千字万金”短故事活动时间为 2026-06-21 至 2026-09-30；
- 活动页宣传短故事分成 10:0、作者 10；
- 活动页宣传超短保底 80-500+ 元/千字、中短保底 100-700+ 元/千字；
- 活动设置奖金池，并说明部分爆款作品有机会进入红果短剧、漫剧改编剧本池；
- 同期“IP 金品共创计划”覆盖男频脑洞、女频脑洞、悬疑惊悚等品类；
- “IP 回响计划”把优质短故事作为短剧 IP 储备进行评估。

以上是平台活动宣传和公开规则，不等于每篇作品都能获得签约、保底、奖金或改编。实际权利义务以作者后台当期规则、签约评估和合同为准。

平台公开的历史短故事说明将短故事描述为 6,000-80,000 字、一次完结，并把 10,000-30,000 字列为较佳区间。该说明不是永久不变的合同条款，投稿前仍须核对当期后台。

### 2.2 尚未确认的关键事实

公开页面不足以确认以下问题，真实投稿前必须通过作者后台最新协议、活动细则或编辑确认：

1. AI 辅助创作的申报、标识、签约和版权边界；
2. 每一档保底的申请条件、评估标准、独家范围和结算条件；
3. 作品被拒后是否允许修改重投、跨活动投稿或跨平台投稿；
4. 合同对信息网络传播权、音频权、短剧权、漫剧权、衍生权和再授权的具体约定；
5. IP 入池与正式改编签约之间的权利和收益差异；
6. 活动结束后基础签约和结算政策是否延续。

未经确认，不得在商业预测中把这些事项当成既定事实。

## 3. 商业假设

### 3.1 核心假设

当前短篇链可以用可控的模型和人工成本，生产达到平台签约门槛的 10,000-15,000 字原创脑洞悬疑短故事；当签约率和单篇到账达到一定水平后，整个投稿批次可以获得正毛利。

### 3.2 必须被市场验证的假设

1. 当前短篇链的成稿质量经过有限人工修改后可以投稿；
2. 脑洞悬疑题材与平台当前需求匹配；
3. 模型调用成本不会吞噬最低档可得收入；
4. 人工修改可以稳定控制在每篇 3 小时以内；
5. 落选稿比例计入后，批次总收入仍能覆盖全部变量成本；
6. 平台允许当前创作流程产生的作品参与签约和结算；
7. 至少有一篇作品产生真实到账，而不是只获得流量或口头反馈。

## 4. 客户、商品与购买理由

### 4.1 直接付费方

第一阶段唯一直接付费方是番茄短故事平台及其签约、分成和活动体系。读者流量、短剧公司和其他平台不作为第一阶段获客对象。

### 4.2 商品定义

第一版商品规格：

| 项目 | 冻结值 |
| --- | --- |
| 平台 | 番茄短故事 |
| 品类 | 脑洞悬疑，避免把血腥猎奇当核心卖点 |
| 篇幅 | 目标 12,000 字；允许约 10,800-14,400 字 |
| 结构 | 12 章，每章约 900-1,200 字，一次完结 |
| 视角 | 第一人称优先，允许因故事需要使用有限第三人称 |
| 开篇 | 前 500 字必须完成入局、异常和行动压力 |
| 中段 | 至少三次有效升级，不允许同类惊吓重复堆叠 |
| 反转 | 必须有可回看验证的前置证据 |
| 结局 | 主线闭环并完成明确情绪回报 |
| IP 倾向 | 高概念、可视化、人物和场景可控、能够拆分主要戏剧节点 |
| 审核 | 每篇必须人工终审 |
| 投稿 | 人工登录、人工发布 |

当前 InkOS 短篇代码默认 12 章、每章约 1,000 字，并支持 12-18 章、每章 900-1,200 字，天然覆盖本商品的目标体量。

### 4.3 商业交付包

每个候选故事形成以下内部交付物：

```text
01-commercial-brief.md        题材、受众、核心冲突、购买理由
02-title-candidates.md        标题候选和选择理由
03-outline.md                 人物、压力链、证据链、反转链、结局
04-manuscript.md              最终投稿正文
05-quality-report.md          平台质量审查
06-compliance-report.md       原创、版权和内容风险检查
07-sales-package.md           简介、卖点、标签、封面文案
08-ip-adaptation.md           视觉场景、主要节点和改编风险
09-human-review.md            人工审核结论与修改记录
```

这些运行产物不得提交 Git。Git 中只保存模板、规则和脱敏汇总。

## 5. 收入模型

收入按可靠性分层：

| 收入层 | 商业地位 | 预算处理 |
| --- | --- | --- |
| 合同明确的保底或稿费 | 核心收入 | 合同确认后纳入预测，到账后纳入实绩 |
| 阅读、听读等平台分成 | 核心收入 | 仅按后台实际结算统计 |
| 活动奖金 | 上行收益 | 基础预算按 0 |
| 短剧、漫剧、版权改编 | 期权收益 | 正式签约和到账前按 0 |

单篇毛利：

```text
单篇毛利
= 实际到账收入
- 模型 API 成本
- 人工选题与修改成本
- 审核成本
- 封面等直接成本
```

批次毛利必须把落选稿计入：

```text
批次毛利
= 批次全部实际到账收入
- 批次全部候选、落选稿和签约稿的变量成本
```

不得用“单篇签约稿收入减单篇签约稿成本”掩盖大量落选稿成本。

## 6. 单位经济与成本红线

第一轮使用目标红线，不把它们写成已验证事实：

| 成本项 | 单篇目标上限 |
| --- | ---: |
| 候选与大纲摊销 | 50 元 |
| 完整成稿模型成本 | 120 元 |
| 其他直接现金成本 | 30 元 |
| 人工修改时间 | 3 小时 |
| 单篇现金成本 | 200 元 |
| 含人工的完全成本 | 350 元 |

真实成本必须由合法模型运行和人工工时记录校准。仓库已有 TASK-004 长篇商业运行成本账本，但短篇链尚未自动接入同一成本记录，需要在试验中手工记录短篇各阶段的模型、token、价格版本和金额。

### 6.1 盈亏平衡示例

以下仅用于说明计算方法，不是收入预测：

```text
若单篇完全成本 = 300 元
若签约作品实际到账 = 1,200 元
盈亏平衡签约率 = 300 / 1,200 = 25%
```

这意味着平均每完成 4 篇至少需要 1 篇实际到账 1,200 元，才能刚好覆盖 4 篇的生产成本。奖金和 IP 收入不得用于降低这个盈亏平衡要求。

## 7. 生产漏斗

### 7.1 第一层：20 个一句话创意

每个创意必须同时包含：

```text
异常规则 + 主角困境 + 主动目标 + 独特代价 + 潜在反转
```

只保留 5 个。立即淘汰：

- 只是给常见模板换人物、地点和道具；
- 只能靠血腥、色情或极端猎奇吸引点击；
- 主角没有主动目标；
- 设定很新，但无法支撑完整因果链；
- 反转依赖临时新增信息；
- 与已知作品或同批候选高度相似。

### 7.2 第二层：5 份故事方案

每份约 1,000-2,000 字，只保留 2 份。方案必须回答：

1. 第一屏发生什么；
2. 主角为什么不能退出；
3. 冲突如何至少升级三次；
4. 中段怎样换挡；
5. 反转的证据提前埋在哪里；
6. 结局给读者什么情绪回报；
7. 是否可以拆成 8-12 个主要戏剧节点；
8. 哪些内容可能触发平台、版权或伦理风险。

### 7.3 第三层：2 篇完整成稿

只有方案审核通过后才进入完整生成，避免把高成本模型调用浪费在弱创意上。

完整成稿依次经过：

```text
大纲生成
→ 大纲审查
→ 大纲修订
→ 完整初稿
→ 正文审查
→ 正文修订
→ 商业包装
→ 人工终审
→ 手动投稿
```

## 8. 商业质量门槛

番茄公开脑洞文指南指出的主要问题包括：开篇切入和代入弱、赛道定位模糊、情节重复、人物行为与设定冲突。本项目将这些问题冻结为第一版质量门槛。

### 8.1 100 分评分表

| 维度 | 分值 | 核心问题 |
| --- | ---: | --- |
| 标题和一句话脑洞 | 10 | 是否能快速讲清差异化购买理由 |
| 前 500 字 | 15 | 是否完成入局、异常和行动压力 |
| 主角目标与人物逻辑 | 15 | 行为是否来自利益、能力和处境 |
| 冲突升级与情绪曲线 | 15 | 是否持续变化而非重复同一冲突 |
| 悬疑证据链 | 15 | 线索是否公平、可验证、有权限来源 |
| 反转合理性 | 10 | 是否有铺垫且改变前文理解 |
| 结局回报与闭环 | 10 | 是否解决主问题并兑现情绪 |
| 原创、版权与合规 | 10 | 是否不存在拼接、仿写和高风险内容 |

决策规则：

- 低于 75 分：淘汰；
- 75-84 分：人工修改后重新审查；
- 85 分及以上：允许进入人工投稿审核；
- 原创、版权、合规、因果链任一硬门槛失败：不得投稿；
- 第一千字、核心反转和结局必须人工逐句检查。

### 8.2 不得优化的错误指标

- 不以 AIGC 检测分数作为唯一质量目标；
- 不为降低所谓 AI 痕迹而故意制造错别字、逻辑缺陷或低质口语；
- 不以生成速度、篇数或字数代替签约和结算；
- 不以活动奖金上限代替实际到账；
- 不以阅读量代替批次毛利。

## 9. IP 改编评估

IP 改编是上行收益，不是基础收入。内部改编评分只用于筛选更有潜力的作品。

作品进入 IP 候选必须满足：

1. 一句话能够讲清高概念；
2. 主角目标和核心冲突可以被镜头表现；
3. 至少有一个可识别的视觉道具或场景；
4. 反转依赖行动和证据，不依赖纯心理解释；
5. 主要人物和场景数量可控；
6. 可以拆分为 8-12 个连续升级节点；
7. 结局具有明确情绪兑现；
8. 不需要大量旁白才能让观众理解；
9. 不把高成本特效当作唯一吸引力；
10. 权利链清晰，不包含未经授权的真实人物、品牌故事或其他作品元素。

“进入改编评估”“进入剧本池”和“正式签署改编合同”是不同状态，商业数据中必须分别记录。

## 10. 人机分工

### 10.1 智能体负责

- 产生差异化选题候选；
- 形成大纲、压力链、证据链和反转链；
- 生成完整正文；
- 检查人物、时间线、权限和因果；
- 检查情节重复和后半段泄气；
- 根据审查意见修订；
- 生成简介、卖点、标签和封面文案；
- 生成 IP 改编分析。

### 10.2 人工商业总编负责

- 最终选题；
- 确认没有模仿具体作品；
- 修改标题、前 1,000 字、核心反转和结局；
- 原创性、版权和内容合规确认；
- 判断作品是否达到投稿标准；
- 阅读合同和活动规则；
- 手动上传和发布；
- 确认后台结算和实际到账；
- 决定是否接受独家、改编或其他授权条件。

人工审核是商业和法律责任边界，不是形式上的点击确认。

## 11. 数据与安全边界

### 11.1 按书隔离

每篇商业短故事分配唯一 `book_id`，短篇链的 `story_id` 作为该书下的内容运行标识。任何成本、投稿和结算记录必须同时绑定：

```text
book_id
story_id
run_id
prompt_version
model
submission_id（如平台提供）
```

### 11.2 数据分类

故事内容：

- 大纲、人物、正文、线索、结局；
- 属于内容生产数据，不进入商业账本。

商业运营数据：

- 模型成本、人工工时、投稿日期、审核状态、合同档位、结算、到账、IP 状态；
- 独立保存，不写入故事权威状态。

敏感数据：

- API Key、Cookie、身份证明、合同、银行卡、平台账号、后台截图；
- 不得写入仓库、普通日志或模型提示词。

### 11.3 Git 边界

不得提交：

- 生成小说正文和正式投稿材料；
- 本地模型运行数据和成本账本；
- 合同、账号和结算证明；
- 密钥、Cookie、日志、数据库和缓存；
- 未脱敏的编辑反馈和平台后台数据。

## 12. 合规与版权控制

1. 不抓取、拼接或仿写他人完整作品；
2. 不使用“参考爆款”要求模型复制具体人物、结构、金句或情节；
3. 不跨作品重复出售相同正文；
4. 不在独家合同冲突时重复授权；
5. 不伪造阅读、签约、稿费或活动数据；
6. 不通过多账号和自动发布绕过平台规则；
7. 不把血腥、色情、迷信、极端伦理伤害当作默认悬疑发动机；
8. 投稿前保留选题、大纲、版本和人工修改记录，用于证明创作过程；
9. 正式签署合同前，人工核对独家范围、期限、地域、媒体、改编权、再授权、违约和解约条款；
10. AI 辅助资格未获得明确确认前，不对平台作虚假陈述。

## 13. 两篇真实投稿试验

### 13.1 目标

使用现有短篇链生成两篇商业样稿，完成人工终审和真实手动投稿，验证流程、成本、平台字段和审核反馈。两篇作品不是规模化生产，也不用于证明商业模式已经成立。

### 13.2 试验题型

#### A：现实规则型脑洞悬疑

核心约束：异常规则必须与主角的现实利益和选择绑定，不做纯规则罗列，不依赖血腥惩罚。

建议方向：

> 主角突然能看见每个承诺的“违约日期”，却发现自己最信任的人没有日期，而是显示“从未生效”。

#### B：身份证据型脑洞悬疑

核心约束：身份反转必须由可追溯证据完成，不能在结尾临时宣布双胞胎、梦境或精神疾病。

建议方向：

> 主角参加自己的葬礼，却发现所有宾客都能认出她，只有母亲坚持说死者才是自己的亲生女儿。

正式生成前，人工仍可在不改变两个试验类型的前提下调整具体选题。

### 13.3 统一参数

| --- | --- |
| 篇数 | 2 |
| 每篇章节 | 12 |
| 每章目标 | 1,000 字 |
| 封面 | 首轮可关闭图片生成，只保留提示词 |
| 大纲审查 | 1 次 |
| 大纲修订 | 1 次 |
| 正文审查 | 1 次 |
| 正文修订 | 1 次 |
| 人工终审 | 必须 |

### 13.4 投稿前检查

- [ ] 作者后台最新规则和活动资格已确认；
- [ ] AI 辅助、原创和版权要求已确认；
- [ ] 标题、简介、正文和标签符合当前后台字段；
- [ ] 第一千字已人工逐句检查；
- [ ] 反转证据在前文真实存在；
- [ ] 结局闭环；
- [ ] 没有明显拼接、模板复用或自我抄袭；
- [ ] 没有未授权真实人物和作品元素；
- [ ] 人工明确批准；
- [ ] 投稿文件不在 Git 跟踪范围；
- [ ] 合同和账号资料不进入模型或仓库。

## 14. 10 篇与 20 篇验证

### 14.1 累计 10 篇

第一批两篇没有出现合规或流程性阻塞后，累计生产和投稿 10 篇，记录：

- 候选数量和淘汰原因；
- 模型、token、模型成本和价格版本；
- 人工工时；
- 投稿活动和题材；
- 审核结果和退回原因；
- 签约档位和合同收入；
- 实际到账；
- 阅读、听读等分成；
- IP 评估、入池、询价和签约状态。

### 14.2 累计 20 篇

只有满足以下条件才进入 20 篇复验：

- 已产生至少一笔真实到账；
- 10 篇批次收入能够覆盖变量成本，或有明确的可修复成本路径；
- 没有版权、拼接、违规和账号处罚；
- 人工修改时间正在下降；
- 后 5 篇质量或签约率不低于前 5 篇。

只有连续 20 篇后仍保持正毛利，才讨论正式产品化和扩量。

## 15. 核心指标

| 指标 | 计算方式 | 用途 |
| --- | --- | --- |
| 方案晋级率 | 完整成稿数 / 故事方案数 | 选题漏斗效率 |
| 投稿率 | 投稿数 / 完整成稿数 | 内部质量稳定性 |
| 签约率 | 签约数 / 投稿数 | 市场适配 |
| 到账率 | 已到账作品数 / 签约作品数 | 收入兑现 |
| 单篇实际收入 | 实际到账 / 已到账作品数 | 收入质量 |
| 万字实际收入 | 实际到账 / 实际字数 × 10,000 | 跨篇比较 |
| 单篇现金成本 | 模型和直接现金成本 / 完整成稿数 | 现金效率 |
| 单篇完全成本 | 现金成本 + 人工成本 | 单位经济 |
| 批次毛利 | 批次到账 - 批次全部变量成本 | 是否真正赚钱 |
| 人工修改时间 | 人工工时 / 完整成稿数 | 自动化有效性 |
| IP 转化率 | 正式改编签约数 / 投稿数 | 上行潜力，单独统计 |

不把生成篇数、总字数、阅读量或入池通知单独当作赚钱成功。

## 16. 止损与扩量规则

| 结果 | 决策 |
| --- | --- |
| 两篇均因流程或资格问题无法投稿 | 暂停生成，先解决平台准入 |
| 10 篇 0 签约 | 停止扩量，复盘选题、开篇、题材和成稿质量 |
| 有签约但批次亏损 | 降低模型与人工成本，不增加产量 |
| 有签约但无到账 | 等待结算，不宣布商业模式成立 |
| 至少一笔到账且 10 篇批次接近盈亏平衡 | 进入 20 篇复验 |
| 连续 20 篇批次毛利为正 | 允许设计正式商业生产功能 |
| 获得 IP 询价或入池 | 单独建版权任务，不混入日常稿费模型 |
| 出现版权投诉或账号处罚 | 立即暂停全部投稿并人工调查 |

建议规模化门槛：签约率不低于 20%、人工修改不超过 3 小时/篇、批次毛利为正。以上是内部经营阈值，不是平台承诺。

## 17. 90 天执行路线

### 阶段 0：准入确认

- 注册和核对合法作者账号；
- 阅读最新活动规则、签约流程和合同样本；
- 确认 AI 辅助和原创要求；
- 冻结投稿字段和人工审核清单。

### 阶段 1：两篇投稿冒烟

- 产生 20 个候选；
- 完成 5 份方案；
- 生成 2 篇完整成稿；
- 人工终审；
- 手动投稿；
- 记录成本和平台反馈。

### 阶段 2：累计 10 篇

- 根据真实退回和签约反馈修订选题与审查规则；
- 不改变题材，不扩平台；
- 记录实际签约、结算和人工工时；
- 完成第一次批次盈亏分析。

### 阶段 3：累计 20 篇

- 只在阶段 2 通过止损门槛后执行；
- 验证签约率和毛利是否可重复；
- 区分稿费、分成、奖金和 IP 收入；
- 决定停止、继续人工生产或进入工程化。

## 18. 工程化路线

本计划不授权立即修改代码。真实市场数据出现前，优先复用现有 `short run`。

如果两篇投稿冒烟通过，建议按独立任务逐步建设：

1. 番茄短故事商业规格和输出模板；
2. 20→5→2 选题漏斗；
3. 开篇、赛道、重复、人物逻辑、证据链和结局质量门槛；
4. 短篇成本、人工工时、投稿和到账账本；
5. 人工投稿包导出和审核工作台；
6. 10 篇真实市场验收；
7. 20 篇毛利复验；
8. 通过后再讨论规模化、其他题材或 IP 改编功能。

仍然禁止：

- 自动登录和自动投稿；
- 多账号运营；
- 大规模正文抓取；
- 复制或重写具体作品；
- 自动接受合同和授权；
- 在没有真实利润前建设视频、配音和内容矩阵。

## 20. 第一阶段成功定义

两篇试验的成功：

```text
真实完成投稿
+ 成本与人工工时可审计
+ 获得可用于迭代的真实平台结果
```

商业模式的成功：

```text
至少一篇实际到账
+ 累计 20 篇后批次毛利为正
+ 无版权、合规和账号处罚
+ 结果能够重复，而非依赖一次奖金或偶然爆款
```

## 21. 结论

本方案不把“AI 能生成短故事”当作竞争优势。真正需要积累的资产是：

- 经平台验证的选题标准；
- 真实签约和退回原因；
- 第一千字、反转和结局的人工编辑方法；
- 每个模型与流程版本的成本和签约表现；
- 可审计的版权、合规和创作过程；
- 能够在计入落选稿后仍保持正毛利的生产漏斗。

第一步是两篇人工投稿试验，不是扩量。第一笔真实到账出现后，再决定是否把有效方法固化为产品能力。
