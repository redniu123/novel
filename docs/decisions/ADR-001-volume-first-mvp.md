# ADR-001：第一阶段采用单本走量小说 MVP

状态：Accepted
日期：2026-07-12

## 背景

项目长期目标包含网络小说创作、成本分析、市场选题、商业总编、读者反馈和运营自动化。若第一阶段同时建设多书并发、平台发布和商业智能层，将无法判断问题来自 InkOS 原版、模型质量、故事状态还是新增业务逻辑，也会显著扩大密钥、账号和内容数据风险。

原版 InkOS 已提供长篇建书、章节规划、写作、连续性审查、修订、人工审核、结构化状态、SQLite 记忆和多模型接入。当前更需要先证明一条单书生产链可以稳定重复，而不是重写核心。

## 决策

- 第一阶段优先完成一本走量小说前 20-30 章的 MVP；
- 不进行多本并行和全自动发布；
- 先验证原版 InkOS，再开发商业运营层；
- 优先通过扩展、组合和外围数据层实现新增能力，不重写核心；
- 保留人工最终审核和人工发布；
- 故事权威状态与商业运营数据分离。

## 原因

- 缩小验证范围，能把模型、流程和状态一致性问题清楚归因；
- 最大化复用原版已经过 2351 项测试覆盖的能力；
- 避免过早引入平台账号、Cookie、自动发布和多租户安全问题；
- 让每个后续能力都能以独立任务、验收标准和回滚边界交付；
- 先获得真实 token、质量和人工修订数据，再设计成本与运营模型。

## 优点

- 更快获得可信的端到端样本；
- 变更范围小，便于同步上游；
- 人工审核降低错误正文和错误状态进入发布环节的风险；
- 商业数据层可以独立演进，不污染故事权威状态；
- 后续是否扩展到多书并行有客观数据依据。

## 代价

- 第一阶段不能验证多书调度和账号运营效率；
- 发布仍需人工操作；
- 市场选题、商业总编和读者模拟的收益暂时无法量化；
- 需要接受原版部分限制，并通过小任务逐项改善；
- 20-30 章成功不等同于超长篇全生命周期已经验证。

## 重新评估条件

- 单书前 20-30 章流程在固定环境中可重复运行；
- 至少完成一次真实模型的规划、写作、审查、修订和人工通过；
- 连续性错误、失败率、人工修改量、token 与实际成本有可审计记录；
- 故事状态与运营数据边界稳定；
- 自动发布涉及的平台规则、账号安全、内容审核和许可证风险完成专项评估。
