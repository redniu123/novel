# ADR-002：连续生成验证采用观察优先

状态：Accepted
日期：2026-07-23

## 背景

项目已经完成走量策略、商业状态、单章编排和成本账本，但真实模型证据仍停留在建书和
单章主链。继续优先建设商业入口、权限和报表，无法证明生成系统能否稳定完成一本小说
的前 20-30 章，也无法判断质量瓶颈实际位于规划、模型、Prompt、上下文、记忆、审查、
修订还是状态结算。

在缺少连续样本时先修改生成系统，会同时改变多个变量，导致后续结果不可比较，也容易
把主观阅读感受误写成技术根因。

## 决策

- 下一总任务定为 TASK-005“真实小说连续生产与生成质量闭环”。
- 首轮使用一本新书和固定配置，目标连续生成 20 章。
- 基线期间只观察和记录，不修改生成系统行为。
- 不预先假设缺陷来自 Prompt、模型或记忆层。
- 缺陷记录必须区分症状、候选归因和已确认根因。
- 只有完成基线或触发明确硬停止后，才能按证据选择生成修复任务。
- 原先在 `volume-production-strategy.md` 对 TASK-005“审核身份与权限”的编号预留被本
  决策取代；该能力保留为后续候选，但不再占用 TASK-005 编号。

## 原因

- 直接服务 ADR-001 的核心目标：证明单书前 20-30 章可控生产。
- 让长距离连续性、重复、节奏、伏笔和状态漂移拥有真实样本。
- 保持模型、配置和系统行为稳定，使跨章比较和缺陷归因有意义。
- 避免继续投入对当前生成质量没有直接帮助的运营基础设施。
- 先取得人工修改量和审查有效性，再决定最有价值的工程修改。

## 代价

- 基线会消耗真实模型时间和费用，即使中途发现明显质量问题也不立即调参。
- 商业入口治理、暂停恢复、审核权限和成本报表继续延后。
- 单本 20 章只证明所选题材、模型和配置下的结果，不能直接外推到所有小说类型。
- 如果遇到状态损坏或连续管线失败，基线可能无法完成，但失败本身是必须保留的证据。

## 安全约束

- 密钥、小说正文、模型响应、数据库和运行日志不得进入 Git。
- 密钥风险、状态损坏、章节覆盖、跨书污染和异常计费配置属于硬停止条件。
- 用户负责最终内容质量判断；自动审查和自动评分不能替代人工审核。

## 重新评估条件

- TASK-005A 已完成 20 章或形成可复现的硬停止证据；
- 已形成跨章缺陷聚类和人工修改量记录；
- 有证据支持至少一个具体生成瓶颈；
- 用户批准针对该瓶颈的修改范围和对照验收方案。
