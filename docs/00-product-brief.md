# 第一阶段产品方向：单本走量小说 MVP

状态：已冻结
冻结日期：2026-07-12
适用范围：InkOS 二次开发第一阶段

## 项目第一阶段目标

第一阶段基于原版 InkOS，打通一本走量网络小说前 20-30 章的可控生产流程。目标系统至少应能够：

- 生成长篇小说所需的故事规划；
- 生成前 20-30 章正文；
- 记录后续可用于统计模型成本的数据基础；
- 控制章节自动修订次数；
- 检查人物、时间线、世界观、资源、关系和伏笔的连续性；
- 保留人工最终审核，由人工决定是否通过；
- 由人工完成最终发布；
- 为后续接入市场选题、商业总编和真实反馈模块保留扩展空间。

本阶段只冻结目标，不开发新增能力。原版 InkOS 已经支持到什么程度，以 [基线分析](02-inkos-baseline.md) 的真实代码和验证结果为准。

## 第一阶段明确不做

- 四本或多本小说并行生产；
- 自动登录番茄小说或其他内容平台；
- 自动发布小说；
- 自动维护多个发布账号；
- 自动爬取大量完整小说正文；
- 根据评论实时修改已经生成或已经发布的正文；
- 头牌小说模式的深度优化；
- 完全无人审核；
- 闭源商业 SaaS；
- 大规模修改或重写 InkOS 核心架构。

## 第一阶段成功标准

- 原版 InkOS 能完成基础安装和构建；
- 原版测试结果被完整记录，失败和跳过项不被隐瞒；
- CLI 能启动，并确认其入口和主要命令；
- Studio 能启动，并确认其项目根目录、端口和访问方式；
- 至少完成一次隔离的小说项目初始化；
- 在具备合法模型凭证时，至少完成一次故事规划和章节生成；
- 能定位章节审查、修订和人工审核流程；
- 能定位故事权威状态、Markdown 投影和 SQLite 记忆系统；
- 能定位模型配置、密钥读取和 API 调用封装；
- 明确哪些能力可直接复用、哪些能力需后续开发；
- 其他开发者能按 Runbook 重复基线验证。

## 当前阶段开发原则

```text
先验证原版，再进行二次开发；
优先扩展和组合，不直接重写InkOS核心；
一次只开发一个可测试、可回滚的小任务；
所有新功能必须具有明确的验收标准；
故事权威状态与商业运营数据必须分离；
origin实际默认稳定分支只保存稳定版本，日常开发在develop和任务分支进行。
```

补充约束：不得提交 API 密钥、Cookie、账号信息、小说正文、测试数据库或本地运行数据；对模型成本、运营分析等新增数据，后续应建立独立数据边界，不能把商业事实混入故事权威状态。

## 分支与任务约定

- `master`：当前 `origin` 默认稳定分支；
- `main`：本地保留的上游兼容分支，不在本轮删除或重命名；
- `develop`：日常集成分支；
- `docs/<topic>`：文档与分析任务；
- `feature/TASK-<number>-<topic>`：独立功能任务；
- `fix/TASK-<number>-<topic>`：独立缺陷修复任务。

不得直接在稳定分支 `master`/`main` 上开发；当前仓库稳定分支以 `origin` 实际默认分支为准。任何任务进入开发前都应有任务单、验收标准和回滚边界。本阶段不创建 TASK-002 之后的实际功能分支。
